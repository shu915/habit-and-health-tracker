# グラフと集計(栄養の比べ・推移・記録のカレンダー)

CLAUDE.md から分けた詳細。仕様を変えたら、ここも直す。

## 栄養の目標との比べ(日の詳細、`meal-nutrition.tsx`)
- 食事が 1 件以上ある日に、左にレーダーチャート、右に数字の表。数字は `meals` の合計の列から `lib/meal-radar.ts` で計算するだけ(AI なし)。チャートは Recharts(`"use client"`、props は数字の配列だけ)
- **軸は 6 つ**(カロリー・たんぱく質・脂質・糖質・食物繊維・塩分。これ以上は読みにくいので増やさない)。目標は、軸ごとの**幅(ゾーン)を薄い帯**で示し、帯の真ん中が 100%(人によって適量が違うので、ざっくり幅の中ならよい。2026-11-06、利用者の決定)。**入力する目標はプロフィールの目標カロリーだけ**で、あとは定数(`meal-radar.ts`)から出す(性別・年齢・体重に左右されない)
  - カロリー = 「目標となるカロリー」= 目標カロリー + その日の追加の運動の消費 / たんぱく質 = 目標カロリーの 13〜20%(÷4。運動の分は足さない)/ 脂質 = 目標となるカロリーの 20〜30%(÷9)/ 糖質 = 46〜69%(÷4。国の目安 50〜65% より少し広げ、他の軸と幅をそろえた)/ カロリーは ±10%(±15% は、幅が 700kcal ほどでゆるすぎた) / 食物繊維 = 20g が 100%(帯 16〜24g)/ 塩分 = 10g が 100%(帯 8〜12g)。どちらも、**日本人の実際の量に近い値**を基準にした(25g・7.5g は現実の食事では厳しすぎて、グラフが突き抜けて、やる気を下げるため。塩分の国の目標は男性 7.5g・女性 6.5g 未満。2026-11-06、利用者の決定)
  - 三大栄養素の幅は、食事摂取基準のエネルギー比の目標量(たんぱく質 13〜20%・脂質 20〜30%・炭水化物 50〜65%。糖質だけ、帯の幅をそろえるために広げている)という記憶に基づく(**年齢別の値は未確認**)。表の「目標」は幅(g)で出し、一言は幅の中なら「目標に近い」。帯は、上端の多角形を薄く塗り、下端を面の色でくり抜いて描く(`meal-radar-chart.tsx`。背景色が変わる場所に置くときは要注意)。食物繊維の 20g は、実際の摂取量に近い値(国の目標量の数字は未確認)。**一般的な参考値で、医療上の指示ではない**(画面にも書く)。目標カロリー未設定なら、カロリー・たんぱく質・脂質・糖質は割合なし
  - **塩分 10g・食物繊維 20g の根拠(2026-11-06)**: 理想の値(国の目標量)を 100% にすると、ふつうの食事でも突き抜けて、やる気を下げるので、実際の摂取量に近い「いつもの量」を 100% にした。塩分: 令和 5 年国民健康・栄養調査の 20 歳以上の平均は、男性 10.7g・女性 9.1g([東京都の資料](https://www.hokeniryo.metro.tokyo.lg.jp/documents/d/hokeniryo/2025-11-11-144205-331))、令和 6 年の全体の平均は 9.6g([薬事日報](https://www.yakuji.co.jp/?p=126889))。国の目標量は、男性 7.5g・女性 6.5g 未満(2025 年版。[京都府の資料](https://www.pref.kyoto.jp/kentai/documents/hyoji2026.pdf))。食物繊維: 令和元年の全国の値が 19g 台([鳥取県の資料](https://www.pref.tottori.lg.jp/secure/1328135/02_kekkagaiyo.pdf)。**ほかの出典では未確認**)。2025 年版の目標量は、WHO の 25g/日以上を参考にしたという記述があるが、年齢別・性別の数字は未確認([厚生労働省](https://www.mhlw.go.jp/content/10904750/001207481.pdf))。平均値は中央値より高めに出る(偏りがある分布)ので、見直すときは、報告書の表の中央値で確かめる
- 向きは軸ごとに違う: 塩分は超えないほうがよい(limit)、たんぱく質は届くほうがよい(reach)、ほかは近いほどよい(near)。表の「一言」は向きに合わせる
- **過ぎた日は通常、書きかけの日(`isFinishedDay` が false)は点線・薄く「途中」と示し、一言は付けない**。描画は 200% で頭打ち(表は実際の割合)。圧縮はしない(目盛りが場所で変わると、表と食い違って読みにくいため)。不規則な日は 150% にすぐ届くので、外側の余白を広く取り、グラフの高さも合わせてある。**各軸のゾーンは、100% を中心に ±20% 前後にそろえ**(うまく整うと、きれいな六角形になる。2026-11-06)、上端は端より内側に置く(超えた分を描く余白のため)。すべての軸で、ゾーンの真ん中 = 100% = 理想のとき、データが帯の真ん中に収まる。`fiber_g`・`salt_g` が null の食事があれば、合計は分かる分だけで、`*` を付けて断る
- 「目標となるカロリー」(計画)と「消費の目安」(現実の推定)は別のもので、名前も分ける(どちらも「目安」と呼ばない)。目標はプロフィールの目標カロリー + その日の運動で、消費とずれていてよい(そのずれが減量のペース)。「この日の結果」は現実の収支(摂取・消費の目安・差)だけを並べ、目標との比べは栄養のレーダーの枠に出す(同じ数字を 2 か所に出さない)

## グラフ全般
- Recharts は幅を測るまで描かないので、**高さを固定にして、サーバーが空の枠で場所を確保する**(レイアウトがずれない。ハイドレーションのテストで固定)。色は `globals.css` の `--viz-*`(dataviz の基準色。ダークモードは OS の設定に従い、変数が切り替える)
- 図は、1 つの図に軸 2 本を作らない(単位が違うものは別の図)。各図に、読み上げ用の要約(`role="img"` の `aria-label`)と、表の形の代替(`<details>`「表で見る」)を付ける(記録のカレンダーは、一覧が表の役目をするので付けない)。注記は、枠の下にまとめず、各図の下に置く。カードの見出しは `text-base font-semibold`
- グラフを書く前に `dataviz` スキルを読む

## 推移のグラフ(ダッシュボード、`trend-section.tsx`)
- 新しい図を足すときは、カードを別ファイルにして、`trend-section.tsx`(データの取得と並び)に渡す。集計は `lib/trend.ts`・`lib/calorie-trend.ts`(AI なし。あとの AI フィードバックの共通の土台)
- **期間の切り替えは 1 つだけで、枠の中のすべての図に効く**(7 / 28 / 90 日、`?range=`、既定 28 日)。28 日 = 4 週で、どの曜日もちょうど 4 回入り、「今の 28 日」と「その前の 28 日」が曜日もそろって比べられる。期間は今日まで(サーバーの日付)。朝の記録が「サーバーの明日」になる日(UTC のサーバーで日本の朝)は、期間の末尾を明日にして入れる(`trendEnd`)。図の間でホバーを連動させる(`syncId`)
- **図の並び**: 睡眠(2 列)→ 体重 | 体脂肪率 → 摂取カロリー(2 列)→ 摂取 − 消費の目安(2 列)。日の詳細と同じ 1 日の流れ
- **体重・体脂肪率**: 1 色(`--viz-series`)。その日の値は薄い点、**7 日移動平均**(その日を含む過去 7 日、記録が 2 日分以上あるときだけ)は 2px の線。記録の無い日は 0 にせず、線を途切れさせる。平均のために、期間より 6 日前からの記録も取る
- **睡眠**: カードの数字は**すべて中央値**(睡眠時間・就寝・起床・中間時刻。平均は徹夜に引きずられ、時刻の平均は日をまたぐと壊れる。最頻値は分単位ではほぼ重ならない)。時刻の中央値は、縦軸と同じ「前の夜の 18:00 を 0 とした分」で取ってから戻す。図は、横軸が起きた日、縦軸が時刻(夜が上の反転軸)、帯の上端が就寝・下端が起床、細い線が中間時刻。起床は、就寝に睡眠時間を足して決める(日をまたぐ判定を 1 か所に保つ)。睡眠時間が出せない日は帯も線も出さない。**縦軸の境は 18:00**(昼夜逆転ぎみの人は想定していない)。反転軸では、いちばん上の目盛りが間引かれるので `interval={0}` を付けてある
- **摂取カロリー**: 日ごとの摂取(棒)と、目標となるカロリー(破線)。目標は、その日に固定した目標カロリー + その日の運動の消費(固定した値が無い日だけ今のプロフィールで補う)。運動の消費は、その日の体重で計算する。**日の行が無い日**は、過ぎた日ならそれ以前でいちばん新しい固定した目標を引き継ぎ(今のプロフィールで過去を書き換えない)、今日・未来なら今のプロフィールの目標、引き継ぐ元が無ければ線を出さない。**食事の記録が無い日は棒を出さない**(0 にしない。「食べなかった」と「記録していない」を分ける)。棒は 0 から。**書きかけの日の棒は薄く**し、見出しの中央値に数えない。**既知の限界**: 食事を一部しか記録しなかった日も、その日の摂取として数える。体重がどこにも無い日の運動は、消費 0 として足す
- **摂取 − 消費の目安**(`calorie-balance-*`): 日ごとの差の棒。0 を境に、消費より少ない日は下(青)、多い日は上(オレンジ `--viz-over`)。消費の目安は「この日の結果」と同じ式(基礎代謝 × その日に固定した活動係数 + その日の運動)で、`energyOverview` を日ごとに呼ぶ(日の詳細と同じ値になることを実 DB のテストで固定)。**食事の記録が無い日と、消費が出せない日は棒を出さない**(記録が無い日を大きな赤字に見せない)
  - 見出しは**差の合計**(過ぎた日で差を計算できた日だけ)と、体重換算(脂肪 1kg = 約 7,200 kcal。**差を計算できた日が 7 日未満なら出さない**: 記録が数日抜けただけで大きく変わり、痩せたように見えるため)。1 日の中央値と「N 日中 M 日」は小さく添える。書きかけの日は数えない
  - **データが不足している日は、合計から除く**(2026-11-06、利用者の決定): 過ぎた日で、**食事の記録が 1 回だけ**、または**摂取が目標となるカロリーの 6 割未満**の日(`lib/sparse-day.ts`)。記録のもれを、ダイエットが進んだ日と誤解させないため。摂取カロリーの中央値、差の合計・中央値・体重の換算、レポートのバッジと AI の分析材料から外し、棒は薄くして、「除いた日数」を図の下に出す。極端に少なく食べた日も、ここに入りうるので、画面は断定せず、「もれていませんか」と尋ねる(日の詳細に出す)。食事が 2 回あれば、数字が普通なら不足としない(朝食抜きなど)。今日と、記録が無い日は対象外。**データがそろった日(不足でない日)が足りないときは、集計を出さない**(摂取カロリーの中央値、差の合計・中央値・体重の換算。最低 3 日、かつ過ぎた日の 3 分の 1 以上。7 日なら 3 日、28 日なら 10 日、90 日なら 30 日。数日の偶然を、確かなものに見せないため。画面は「データがそろった日が少ないため…出しません(いま N 日、M 日以上で出ます)」と出す)。レポートの摂取の中央値も同じ規則。累積の線の図は、まだ作らない(棒に重ねると軸が 2 本になる)
- 既知: ページ送り(`?page=`)と期間(`?range=`)のリンクは、お互いのパラメータを引き継がない

## 記録のカレンダー(GitHub の草風。「日々の記録」の枠の中、一覧の上)
- 列が週(月曜始まり)、行が曜日、1 マス = 1 日。**濃さは、その日に記録した種類の数(0〜5)**: 朝の記録(体重・体脂肪率・睡眠のどれか)・食事・運動・良かったこと・今日の気づき(空白だけは数えない)。量(食事の件数など)は見ない。青の 5 段階(0 は格子の灰色)
- **期間は直近 53 週(約 1 年)で固定し、狭い画面(md 未満)では直近 13 週(約 3 か月)だけ**を見せる(古い週を CSS の `hidden md:block` で隠すだけ。グリッドは列方向の自動配置で、隠した要素は飛ばされるので列がずれない。マスの大きさは列の幅で決まる=横スクロールなし)。週の数で決めると列がそろう(「3 か月」は日数がぶれて端の週が欠ける)。推移の期間の切り替えとは別の枠
- 各マスはその日の詳細へのリンク(`prefetch={false}`)。ホバーで日付と記録した種類(`title`)。**Tab で止まるのは記録のある日のマスだけ**(記録の無いマスは `tabIndex=-1`。371 個を通らずに済む)。今日の印(枠)は付けない(右端の最後の日で、見た目が悪いため。`aria-current="date"` は残す)
- 今日より後で記録の無い日のマスは出さない(サーバーの明日に記録があれば出す。サーバーの今日が日曜のときは、明日が升目の外で出ない。割り切り)。記録がまったく無い人には出さない
- 自前の CSS グリッドで、サーバーだけで描く(ライブラリは比べて見送った: 升目だけの部品で、依存の追加の手間とブラウザ側の描画の確認のほうが重い)。4 つの表を期間ぶんまとめて 1 回ずつ取る(`lib/record-kinds.ts`。日記の本文は読まず、気づきは空かどうかだけを DB 側で判定)

## 長期レポートのグラフ(四半期・年。`weekly-chart.tsx`・`weekly-cards.tsx`、2026-11-09)
- **1 本 = 1 週間**(月曜始まり。日足・週足・月足の「週足」)。四半期で約 13 点、年で約 52 点。保存した日ごとの数字(スナップショット)から、`lib/weekly-points.ts` が、週ごとにまとめて描き直す(AI は使わない)。月ごとの点(3〜12 点)は少なすぎ、日ごと(最大 365 点)は細かすぎるため
- **線 + 薄い帯**(睡眠・体重・体脂肪率): 線はその週の中央値、帯はその週の最小〜最大(帯が太い週は、揺れが大きい週)。ろうそく足にはしない(体重で「上がった・下がった」に色の意味がつき、減ったことを褒めない方針と合わない。見慣れない人には、読みにくい)。**記録が少ない週(睡眠・摂取は 3 日、体重・体脂肪率は 2 日に満たない週)は、点を出さず、線を途切れさせる**(0 にしない)
- **棒**: 摂取カロリー(週ごとの、1 日の摂取の中央値。目標となるカロリーの破線つき。データ不足の日と書きかけの日は除く)、運動した日数(0〜7。0 の週は「ふだんどおり」)
- **栄養素は、グラフにしない**(スナップショットに、食事ごとの栄養素が入っていないため。文章だけ)
- 軸は 1 本・高さ固定(200px)・読み上げ用の説明・表の形の代替(「表で見る」)は、日ごとのグラフと同じ。週の区切りは、期間の端で 7 日に満たない週が出る

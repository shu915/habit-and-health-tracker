# 画面の規則

CLAUDE.md から分けた詳細。仕様を変えたら、ここも直す。

## 画面の規則
- **アカウントのメニュー(`user-menu.tsx`)**: ヘッダーのメール(スマホ幅は「アカウント」+ 矢印)を**押して開く**(マウスを乗せる形にしないのは、タッチでも同じ動きにするため)。開くと、ログイン中のメールと、「アカウントの設定」(`/account`)・「ログアウト」。閉じるのは、もう一度押す・外を押す・Esc・項目へ移る。キーボードは、ボタンで ↓ を押すと開いて先頭へ、↑ ↓ Home End で移る。ヘッダーに別のログアウトは無い
- **アカウントのページ(`/account`。`account-view.tsx`)**: メールアドレス、ログイン方法(メールのリンク「使えます」、Google「連結済み・未連結」)、区切り線の下にログアウト。**状態は、名前の横の小さな丸いラベル(文字つき。色だけに頼らない)、操作は、右端のボタン 1 つ**で、場所も形も分ける(並べると混同された)。狭い幅は、文の下に操作。**失敗の文は、行の下に全幅で出す**(ボタンの下だと、右側が広がって行全体が縦に並んだ。`google-link-controls.tsx`)。Google の細かい説明は折りたたむ。ログイン画面には、環境変数がそろっているときだけ「Google でログイン」を出す(未連結で戻されたときは理由を出す)。方針は `docs/auth.md`
- パス: `/reports`(AI レポートを作る・一覧。`docs/ai-feedback.md`)・`/reports/[id]`(レポートの表示)。ダッシュボードには、ボタン 1 つ(「レポートを見る・作る」)だけを置く(ダッシュボードは、いまのデータで縦に長いため)。**月次レポートの一覧は、新しい月から 12 件ずつ**(`?page=`。12 件 = 1 年ぶん)。随時の直近 4 週間は、ページの外に、最新の 1 件だけ出す。**四半期レポート(3 か月)と年次レポート(12 か月)は、月次レポートの下の、別々の枠**(画面の名前は、随時・月次・四半期・年次): それぞれの枠に、選べる期間(新しい期間が先。初期値は、解禁された最新の期間)・作れる条件(使える月 N / 必要な月)・作成済み(見るリンク)・作成中、次の解禁日と、あと何日かを出す。一覧は、新しい期間から(件数が少ないので、ページ分けしない)。`/reports/[id]` の長期レポートは、週ごとのグラフ(`docs/charts.md`)。ページ分けは、取ってきた一覧を `lib/report-pages.ts` で切る(件数が少ないため)
- **レポートの PDF 保存(印刷)**: `/reports/[id]` の「PDF で保存(印刷)」ボタンは、ブラウザの印刷(`window.print`)を開く。サーバーで PDF を作らない(ヘッドレス Chromium は Vercel で重く、PDF 専用の部品は画面と二重の保守になるため)。見た目は CSS で決める(`globals.css` の `@media print`: 白い紙・黒い字、A4、余白 14mm、背景色も印刷、白いカードに細い枠)
  - ヘッダー・「戻る」・ボタン・項目へ飛ぶリンクは `print:hidden`。カード・バッジ・気づきの枠は `print:break-inside-avoid`、見出しは `print:break-after-avoid`
  - **改ページ**: グラフのある睡眠・体・食事は、それぞれ新しいページから。文章だけの運動・気持ち・日記・記録の習慣は、運動の前だけ改ページして 1 ページにする(`report-view.tsx` の `PRINT_PAGE_START`)。**改ページの指定は、月次・四半期・年次で共通**なので、1 つに合わせて直すと、ほかが崩れる(運動の前の改ページをやめたら、四半期が崩れて戻した)。1 ページ目はタイトル・バッジ・総合評価
  - 月次の食事は、カード 2 つで 1 ページが埋まるので、**印刷のときだけ**、摂取カロリーと摂取 − 消費のカードを縮める(「表で見る」と図の読み方の文を `print:hidden`、余白を `print:p-3`・`print:gap-1.5`)。**グラフの高さは印刷でも変えない**(CSS だけで枠を低くすると、グラフが描き直されず、下のカードに食い込む)。体重と体脂肪率のグラフは、印刷でも左右に並べる(`print:grid-cols-2`)
  - 印刷のあいだだけ、タブの題名をファイル名の案にする。**ファイル名は「アプリ名_種類_期間」**(`reportFileName`): `habit-health_月次_2026-10` / `_四半期_2026-Q3` / `_年次_2026` / `_随時_2026-10-10_2026-11-06`
  - **新しい部品を足すときは、紙で要るか(要らなければ `print:hidden`)、途中で切れてよいか(困るなら `print:break-inside-avoid`)を考える**。実際の見え方は、Chrome と Safari の印刷プレビューで確かめる(自動のテストでは分からない)
- パス: `/login`(未ログインは他のページから `/login` へ)/ `/` ダッシュボード / `/profile/edit` / `/days/[date]`(詳細)と、その下の `edit`・`meals/...`・`exercises/...`・`positive`(良かったこと)・`reflection`(今日の気づき)
- **閲覧と編集は別のパス**(`?mode=edit` は使わない。閲覧ページが `searchParams` を読まずに済む)。保存は Server Action で、日付・id はページが bind して渡す(フォームの入力にしない)
- 今日の気づきは朝の記録と別のパス(朝の体重だけ入れたい人に 8 行の欄を見せない)。保存は同じ `saveDay` で `reflection` だけを渡し、朝のフォームは `reflection` を送らない
- **データが不足している日**(食事が 1 回だけ、または摂取が目標の 6 割未満の過ぎた日)は、日の詳細の「この日の結果」で、差を出さず(「—」)、「記録にもれはありませんか?」と尋ねる(食事を追加するリンクつき。赤にしない)。推移のグラフでは、棒が薄くなり、合計から除く(`docs/charts.md`)
- **日の詳細の並び**: 朝の記録 → この日の結果(過ぎた日だけ)→ 栄養の比べ(レーダー)→ 食事 → 運動 → 良かったこと → 今日の気づき。1 日の流れの順。栄養の比べは結果の直下に置く(運動の枠のすぐ上だと運動の内訳に見え、食事の枠の中だと「食事を追加」と行が離れる)
- **ダッシュボードの並び**: プロフィール → 日々の記録(一覧とカレンダー。毎日の操作なので上)→ 推移(ときどき見る)
- **一覧は、記録のある日だけを、新しい日から 14 件ずつ**(`?page=`)。記録の無い日の行は出さない(記録ゼロの人に「記録なし」の行が並ぶのが邪魔なため)。記録ゼロのときは案内 1 行だけ。範囲外の `page` は最後のページに寄せる
- **一覧の列**: 日付 / **睡眠時間** / 体重 / **摂取(1 行。「1,420 kcal」。データ不足の日は、数字を薄くして「不足」と添える)** / 気づきの冒頭。一覧の役目は、日々の記録を眺めて、開く日を選ぶこと。**食事の回数・睡眠の中間時刻・体脂肪率・運動は出さない**(推移のグラフと日の詳細で見られる。列が多いと眺めにくい)。摂取・データ不足の判定は、推移のグラフと同じ関数(`lib/day-list-summary.ts`)。狭い画面は、日付(年を省いて「11-05」)・睡眠・体重・摂取だけ。気づきの列は、入りきらないとき、表の枠の中で横にスクロールする(最低 12rem)
- **日々の記録の枠の並び**: 見出し → 記録のカレンダー → 一覧の直上の行(左に一覧の範囲、右に日付欄と「開く」)→ 14 件の一覧 → ページ送り。日付欄は一覧の補助(一覧に出ない日を開く入口)なので、カレンダーを挟んで離れないよう、一覧のすぐ上に置く
- **記録の無い日へ入る入口**: ダッシュボードの日付欄(初期値は今日。「開く」は詳細ページへ。入力画面ではない)、記録カレンダーのマス、日の詳細の「次の日 →」の今日へのジャンプ。サーバーは、2020-01-01 から翌日までの日付を許す(下限は、日数ぶん日の行を作って DB を肥大させないため。`EARLIEST_RECORDABLE_DATE`)。上限は、翌日まで(夜中の記録や時計の少しのずれへの余裕。時計は日本時間に固定してあるので、タイムゾーンのためではない。`isRecordableDate`)。画面では未来を選べない
- **「← 前の日 / 次の日 →」は、記録のある日だけを行き来する**(`getAdjacentDays`)。行き先が無いときも、消さずに薄い押せない表示で同じ場所に残す(連打しても「次の日」の位置が動かない)。「次の日 →」だけは、次の記録が無くても今日より前なら今日へ飛べる(`lib/day-nav.ts`。明日へは行かない)
- **ボタン**(`components/button.tsx`): 決定する操作だけ深い緑(保存・編集・AI で推定する)、弱い操作はグレーの塗り(戻る・キャンセル・提案・写真を選ぶ)。枠線だけのボタンは見つけにくい。行は `FormActions` で中央寄せ、並びは「キャンセル、決定」(決定が右)、削除は左の別のセル、削除の確認も「やめる、削除する」。フォーム下のボタンは同じ大きさ(`size: "action"`)で、色だけで区別する。決定が 2 つ出るときは本命だけ緑。角丸は バッジ 6px・ボタン 8px・白い面 12px(`rounded-sm`・`rounded-md`・`rounded-lg`)。新しいフォームもこの並びにする
- **スマホ幅(日の詳細から着手)**: 基準は 375px。横並びは `sm:`(640px)以上だけにして、狭い画面では縦に積む(横スクロールは表だけ)。食事の行は「バッジ・時刻・kcal」の次の行に名前、運動の行はその下に「種類・強さ・分」とメモ。結果のタイルは 1 列。栄養の表は枠の中だけ横にスクロール。全画面が対象
- プロフィールの目標値(体重・カロリー)は「提案」ボタンで入力欄を埋めるだけで、保存しない(本人が確認して保存)。計算は AI なしの式(`lib/nutrition.ts`)。18 歳以上だけが対象で、「医療上の指示ではない」と画面に出す。精度は目安(±10〜15%)
- **現在の体重・体脂肪率は、各欄の隣の「直近の記録から入れる」ボタン**(押した欄だけ)で、朝の値が入っている新しい 5 日分(項目ごと。足りなければあるだけ)の**中央値**を、欄に入れる。保存はしない(「提案」と同じで、本人が確認して保存)。自動で書き換えない: 本人が決めた値を、勝手に変えないため。中央値にするのは、体組成計の値が水分や食事でぶれ、極端な日に引きずられないようにするため(`lib/recent-measures.ts`、読むのは `getRecentMorningMeasures`)。記録が無い欄のボタンは押せない(どちらも無ければ、ボディデータの下の説明にその理由を出す)。推移のグラフには使わない(毎日の値と移動平均で見せる)
- ウエストはプロフィールの現在の値だけ(日ごとの列も履歴も無い。上書き)。月末の 3 日間、今月まだ保存していなければ更新の帯を出す。判定は `profiles.waist_measured_on` で、ウエストの値を変えて保存したときだけ今日になる
